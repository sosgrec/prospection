# Dossier de suivi

Les documents qui décrivent l'appli et sa vie. Les fils du projet ne se voient pas entre eux : ces documents sont leur mémoire commune. Chaque fil les relit avant d'agir et met à jour ceux qu'il touche **dans la même demande de fusion que le code**.

| Document | Ce qu'il contient | Tenu à jour par |
| --- | --- | --- |
| [cahier-des-charges.md](cahier-des-charges.md) | Le besoin, les contraintes, les exigences du directeur, ce qui est hors sujet | Rarement, sur décision |
| [fonctionnalites.md](fonctionnalites.md) | Ce que fait l'appli, écran par écran, avec la version d'arrivée | Les fils Évo |
| [bugs.md](bugs.md) | B-001, B-002… : ce qui se passe, gravité, état, version de correction, test | Les fils Bug |
| [decisions.md](decisions.md) | D-001, D-002… : date, ce qui est décidé, pourquoi | Tous les fils |
| [versions.md](versions.md) | Journal des versions : numéro, date, une phrase | À chaque « En prod » |
| [cahier-de-test.md](cahier-de-test.md) | Tests automatiques et vérifications à refaire dans la Recette | Les fils Évo et Bug |
| [securite-rgpd.md](securite-rgpd.md) | Fiche du registre, mesures en place, contrôles faits, points ouverts | Les fils Sécu |
| [reprise.md](reprise.md) | Tout reconstruire : téléphone perdu, version qui gêne, hébergeur disparu | À chaque changement d'hébergement |
| [passation-2026-11-19.md](passation-2026-11-19.md) | Point de départ du projet, gardé tel quel pour l'historique | Personne |

Deux documents ne sont pas ici, parce que le dépôt est public : la **liste des idées** (I-xxx) et le **carnet d'apprentissage** vivent dans la mémoire du projet Claude, qui reste privée.

**Aucune donnée de client dans ce dossier ni ailleurs dans le dépôt** : pas de nom, de numéro, d'adresse de client, même dans la description d'un bug. On décrit la situation (« un contact avec deux téléphones ») et on la recrée avec des données fictives.
